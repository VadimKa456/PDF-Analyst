- шаги воспроизведения;
- потенциальное влияние;
- при наличии — минимальный пример (без конфиденциальных данных).

Мы подтвердим получение в течение **3 рабочих дней** и постараемся выпустить
исправление в течение **30 дней**. После исправления уязвимость будет описана
в релизе с указанием автора.

## Что считается уязвимостью

- Утечка полных PDF или текста документов в облако при локальном режиме.
- Передача API-ключей в логах или ответах API (ключи маскируются).
- Произвольное выполнение кода при обработке PDF.
- Обход проверки чисел в ответе LLM (добавление чисел, отсутствующих в данных).

## Защита локального desktop API

В Windows desktop-режиме сервер привязывается только к `127.0.0.1`. При
каждом запуске создаётся новый случайный секрет сессии; браузер получает его
только в cookie `HttpOnly`, `SameSite=Strict` при обычной верхнеуровневой
навигации к приложению. Все маршруты `/api` требуют эту сессию. Дополнительно
проверяются ожидаемые `Host`, `Origin` и Fetch Metadata заголовки.

Это снижает риск доступа к локальному API с посторонних сайтов и при DNS
rebinding, но не является границей безопасности против вредоносной программы,
работающей от имени того же пользователя Windows. В обычном server/dev-режиме
desktop-защита не включается автоматически: не открывайте такой сервер в LAN
или интернет без отдельной аутентификации, ограничений сети и TLS.

## Ограничения обработки PDF и исходящих AI-запросов

Обработка PDF ограничена следующими ресурсами: до 500 страниц, жёсткий предел
размера файла 1 ГБ (дополнительно действует пользовательский лимит загрузки),
до 500 000 символов извлечённого текста на страницу и 5 000 000 символов на
документ. OCR и предпросмотр ограничивают растр 12 млн пикселей; разрешение
OCR при необходимости снижается, а если безопасный минимум 150 DPI недостижим,
страница пропускается с предупреждением. Предпросмотр может снижаться до 36 DPI.
На странице сохраняется не более 100 таблиц; слишком большие таблицы пропускаются.
Общий бюджет одного документа — 900 секунд; он проверяется между страницами и
основными этапами обработки (не прерывает уже выполняющийся нативный вызов).
За один multipart-запрос можно передать не более 20 PDF.

Удалённые OpenAI-compatible и Ollama endpoints должны использовать HTTPS.
Обычный HTTP разрешён только для loopback (`localhost`, `127.0.0.0/8`, `::1`).
Частные/служебные IP-литералы и локальные DNS-суффиксы отклоняются. Перед каждым
TCP-подключением DNS-ответ проверяется заново: если хотя бы один адрес не является
публичным (или loopback для localhost), соединение блокируется; TCP подключается
к проверенному IP, при этом TLS продолжает проверять исходное имя хоста. Переменные
proxy окружения не используются, HTTP-редиректы отключены. URL не может содержать
встроенные логин/пароль, query или fragment. Пользователь всё равно должен
указывать только доверенный endpoint и осознанно выбирать провайдера.

## Общие рекомендации

- По умолчанию используйте `AI_PROVIDER=none` — обработка полностью локальная.
- Не открывайте порт `8000` в интернет без reverse proxy, авторизации и TLS.
- Храните `.env` и API-ключи вне Git (файл уже в `.gitignore`).
- Для сканов используйте проверенный Tesseract с языками `rus`/`eng`.
